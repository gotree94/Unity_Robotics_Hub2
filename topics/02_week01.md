#### 1.2 실습: 개발 환경 설치 (1.5시간)

> 본 과정의 실습 환경은 `wsl --install --no-distribution`으로 WSL은 설치했지만 별도 배포판(Ubuntu 등)을 설치하지 않은 Windows 환경입니다.
> 이에 따라 ROS 2 실행 환경은 **Windows용 Docker + VcXsrv(리눅스 GUI 표시) + VS Code(원격 개발)** 조합으로 구축합니다.

**Step 2: ROS 실행 환경 구축 (Docker 기반)**

##### 02_2 Docker 설치하기

도커(Docker)는 프로그램을 실행하는 데 필요한 모든 준비물을 한 번에 담아주는 가상 상자라고 생각하면 됩니다. 이 상자 안에는 프로그램뿐만 아니라, 실행에 필요한 라이브러리와 설정까지 모두 들어 있습니다. 그래서 내 컴퓨터가 Windows이든, Linux이든, 또는 다른 사람의 PC이든 상관없이, 이 상자만 있으면 항상 같은 환경에서 같은 방식으로 프로그램을 실행할 수 있습니다.

1. **다운로드 사이트 검색**: `[docker for windows download]`를 검색한 후 Docker 공식 사이트로 들어갑니다.
2. **다운로드**: [Docker 다운로드] 버튼을 클릭하여 프로그램을 다운로드합니다.
3. **설치**: [Docker 설치] 기본 상태로 설치를 진행합니다.
4. **재부팅**: [Docker Accept] 설치 마지막 창에서 [Close and restart] 버튼을 눌러 컴퓨터를 재부팅합니다.
5. **첫 실행**: [Docker Skip] 재부팅 후, 다음 창이 뜨면 [Accept] 버튼을 누릅니다.
6. **로그인/건너뛰기**: [Docker 실행] 다음 창에서 [Skip] 링크를 누릅니다.
7. **백그라운드 확인**: [Docker 창 닫기] 다음 창이 뜨면 도커가 구동됩니다. 창을 닫아줍니다. 도커 프로그램은 백그라운드로 실행되고 있습니다. (다음 창도 닫아줍니다)
8. **실행 확인**: [Docker 백그라운드 확인] 하단 작업창에서 Docker(숨겨진 아이콘 표시)를 클릭한 후, 도커가 백그라운드로 실행되고 있는 것을 확인합니다.

##### 02_3 VcXsrv 설치하기

VcXsrv는 Windows 환경에서 리눅스용 GUI 애플리케이션의 화면을 볼 수 있게 해주는 Windows용 X 서버 프로그램입니다. WSL이나 원격 리눅스 시스템에서 실행되는 그래픽 프로그램의 출력을 사용자의 Windows 바탕 화면에 띄워주는 역할을 합니다.

1. **다운로드**: [VcXsrv 다운로드] 아래 사이트에서 VcXsrv 프로그램을 받아 설치합니다.
   ```
   https://sourceforge.net/projects/vcxsrv
   ```
2. **설치**: [VcXsrv 설치] 기본 상태로 설치합니다.
3. **첫 실행**: [VcXsrv 실행] VcXsrv 프로그램을 처음으로 실행합니다.
4. **Display 설정**: [Display number 설정] Display number를 0으로 설정합니다.
5. **마침**: [VcXsrv 마침] 다음 > 다음 > 다음 > 마침 버튼을 차례로 눌러줍니다. VcXsrv 프로그램은 백그라운드로 실행되고 있습니다.
6. **실행 확인**: [VcXsrv 백그라운드 확인] 하단 작업창에서 VcXsrv가 백그라운드로 실행되고 있는 것을 확인합니다.

##### 02_4 VS Code 설치하기

VS Code(Visual Studio Code)는 마이크로소프트가 개발한 무료이며 가볍고 강력한 코드 편집기입니다. 다양한 프로그래밍 언어(Python, JavaScript, C++ 등)를 지원하며, 디버깅, Git 통합 등의 필수 기능을 기본으로 제공합니다.

1. **다운로드 사이트 검색**: [VS Code 검색] `[vscode download]`를 검색한 후 공식 사이트로 들어갑니다.
2. **다운로드**: [VS Code 사이트] [VS Code 다운로드] Windows용 프로그램을 다운로드합니다.
3. **설치**: 기본 상태로 설치를 진행합니다.
4. **실행**: [VS Code 설치] VS Code를 실행합니다.
5. **원격 개발 확장 설치**: [Remote Development 설치] [확장 팩]에서 [Remote Development] 확장팩을 검색한 후 설치합니다.

##### 02_5 Docker 컨테이너 구동하기

Docker 컨테이너는 프로그램과 실행 환경을 하나로 묶은 격리된 상자입니다. 덕분에 어떤 컴퓨터에서도 동일하게 프로그램을 실행할 수 있습니다. 여기서는 ROS 2 Humble 실행 환경을 지원하는 Docker 이미지(`ros:humble`)를 다운로드 받아 사용합니다.

1. **PowerShell 실행**: [PowerShell 검색] 검색창에서 `power`를 검색한 후 [Windows PowerShell] 프로그램을 실행합니다.
2. **컨테이너 실행**: [PowerShell 실행] 다음과 같이 `ros:humble` 도커 컨테이너를 실행합니다.
   ```powershell
   docker run -it --name ros_humble1 -p 8765:8765 -v /mnt:/mnt --privileged -v /dev:/dev -e DISPLAY=host.docker.internal:0.0 -e LIBGL_ALWAYS_INDIRECT=0 ros:humble
   ```
   > **⚠️ 참고**: 도커 컨테이너 최초 실행 시에는 컨테이너 이미지를 다운로드 후 실행하기 때문에 다소 시간이 걸립니다.
3. **접속 확인**: ros:humble 도커 컨테이너에 접속한 것을 확인합니다.
   - `ros:humble` 이미지는 우분투(Ubuntu) 22.04(Jammy Jellyfish)을 기본 운영체제(Base OS)로 사용하는 컨테이너 이미지입니다.
   ```bash
   cat /etc/os-release
   ```
4. **⚠️ 컨테이너 재접속 방법** (PowerShell을 닫았다가 다시 열었을 때):
   - `docker run ...`은 이미지로 **새 컨테이너를 만들면서** 실행하는 명령이므로, 다시 실행하면 `ros_humble1` 이름이 이미 존재한다는 오류가 나며 실패합니다.
   - 또한 `docker run -it`으로 붙어 있던 PowerShell을 닫으면 컨테이너도 함께 종료(Exited)되는 경우가 많습니다.
   - 이때는 새로 만들지 말고 **기존 컨테이너를 재사용**합니다.
   ```bash
   docker ps -a                              # 컨테이너 상태 확인 (Exited 또는 Up)
   docker start ros_humble1                   # 종료(Exited)되어 있으면 재시작
   docker exec -it ros_humble1 bash           # 컨테이너 접속 (최초 실행 이후의 접속 명령)
   ```
   > `docker run`은 최초 1회만 실행하면 됩니다. 이후에는 위의 `start` → `exec`로 접속하며, 여러 창을 동시에 접속하려면 위의 재접속 방법을 사용합니다.

**Step 3: Unity Robotics Hub 클론**
```bash
git clone https://github.com/Unity-Technologies/Unity-Robotics-Hub.git
```

**Step 4: ROS TCP 엔드포인트 설치 (Docker 컨테이너 내부)**
```bash
# 먼저 ros_humble1 컨테이너에 접속합니다.
# 컨테이너가 종료(Exited) 상태라면 아래 명령으로 재시작 후 접속합니다.
docker start ros_humble1
docker exec -it ros_humble1 bash

# 컨테이너 내부에서
mkdir -p ~/ros_ws/src
cd ~/ros_ws/src
# ⚠️ main 브랜치는 ROS 1 전용입니다. ROS 2에서는 반드시 main-ros2 브랜치를 사용합니다.
git clone -b main-ros2 https://github.com/Unity-Technologies/ROS-TCP-Endpoint.git
cd ~/ros_ws
colcon build
source install/setup.bash
```
